CVE-2026-98432：修复与缓解

发表于2026-11-03|更新于2026-11-05|工具和软件
|字数总计:4k|阅读时长:14分钟|阅读量:

最近，LINUX DO 上关于 CVE-2026-98432 临时缓解措施的讨论，让这个 Linux 内核漏洞受到不少关注。对于运行网站、监控和其他自建服务的人来说，最需要弄清楚的是：自己的系统是否受影响，发行版有没有提供补丁，以及暂时不能升级时能做什么。

这个 CVE 在 2026 年 10 月 15 日已经公开。10 月 27 日，Anthropic 发布研究，介绍了针对 MPTCP 监听服务的零点击远程 root 命令执行演示，进一步引起关注。演示证明了特定环境下的利用能力，不能据此推断所有 Linux 服务器都能以同样方式被攻陷。漏洞公开信息与研究原文分别说明了这两个时间点。

本文的官方进展核对时间为 2026 年 11 月 4 日，悉尼时间。处置上应优先安装发行版的修复内核；需要等待升级窗口时，再通过限制入口和过滤报文降低暴露面。

漏洞发生在哪里

CVE-2026-98432 位于 Linux 内核处理 IPv4 TCP 连接的路径中。问题与并发处理连接请求时的内存生命周期有关：一个处理过程释放了 IP 选项相关的内存，另一个处理过程还在读取它，形成 use-after-free，也就是“释放后使用”。

漏洞可能造成内核崩溃、信息泄露或内存破坏；研究人员已经在使用 MPTCP 监听服务的环境中演示了远程代码执行。更细的函数关系与 RCU 修复说明，可以查看 Linux 内核 CVE 公告。

临时缓解减少可达流量，修复内核解决漏洞本身

漏洞本身不限于 MPTCP。 Ubuntu 官方明确指出，关闭 MPTCP 的建议主要针对已描述的研究利用方式，安全更新才是其认可的修复途径。因此，下文关闭 MPTCP 的操作只能作为补充措施，不能用来判定系统已经安全。Ubuntu 官方解释

官方修复进展

上游合入修复之后，发行版还需要回移补丁、构建软件包并完成测试。判断服务器状态时，要看正在使用的发行版和内核分支。

项目截至核对时的状态
Linux 上游已修复并回移到维护中的稳定分支。披露说明
Ubuntu22.04、24.04、26.04 的通用内核修复在 -proposed 测试仓库。官方进展
DebianBookworm、Trixie 的安全仓库已提供修复。安全跟踪
RHEL8、9、10 的标准 kernel 包已有修复公告。CVE 页面
Amazon LinuxAmazon Linux 2、2023 已提供修复内核。AWS 公告

Debian 的 linux 源包中，Bookworm 从 6.1.190-1 起修复，Trixie 从 6.12.113-1 起修复。源包版本与 uname -r 的输出格式不同，需要对照已安装软件包。RHEL 的具体小版本、实时内核和 OpenShift 则应分别查询对应公告。

Ubuntu 的情况需要多看一层。Canonical 在 11 月 2 日的博客中列出了三个通用内核测试包：22.04 的 5.15.0-203.213、24.04 的 6.8.0-149.149、26.04 的 7.0.0-43.43。这些版本不能直接套到 linux-aws、linux-azure、HWE 或其他内核分支上。

同一篇官方博客将 Ubuntu 26.10 的 7.3.0-10.10 标为已修复，但本次核对时，CVE 跟踪页的对应项仍显示 work in progress。两处状态存在差异，安装前应继续确认当前仓库、具体包名和安全公告，避免只凭一张版本表作判断。

AWS 在其 11 月 2 日更新的公告中表示，尚无证据表明该漏洞已被利用。这是该公告当时掌握的情况，不应写成对所有环境的保证。

检查监听端口与 MPTCP

net.mptcp.enabled = 1 表示允许创建 MPTCP socket，不代表应用已经在使用它；值为 0 或列表为空，也不能排除这个 CVE 的其他触发路径。若 ss 不认识 -M，需要使用支持该选项的 iproute2 工具，不能把命令失败当成“没有 MPTCP”。MPTCP 开关定义

监听在 0.0.0.0 或 [::] 表示绑定了通配地址，是否能从公网访问，还取决于路由、安全组和防火墙。容器与 Kubernetes 还涉及转发路径和独立网络命名空间；下面的主机 input 规则与主机 sysctl，不能自动覆盖这些路径。

暂时无法升级时的完整处置

下面三类措施作用不同：来源限制减少可达对象，报文过滤减少特定流量进入漏洞路径的机会，关闭 MPTCP 则减少已描述利用方式所需的条件。它们都不能替代内核补丁。过滤规则还会影响确实需要 IPv4 Options 的业务，应先验证业务需求和连通性。Red Hat 缓解说明
